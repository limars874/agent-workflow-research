# ROADMAP · flow-light(陪伴型)

> `flow-*` 家族的陪伴轻量版。采用现成好 skill(mattpocock)+ 自建**项目记忆层** + 按需补真实缺口。
> ⚠️ **活文档**:会随实测不停改。checklist 做完就勾 `[x]`。**痛点驱动,不预先建全。**

---

## 一、目标

**一句话**:在高上下文可持续的 host(Codex)上,靠"采用现成好 skill + 项目记忆层",让 AI 陪伴式开发时**全程不跑偏、跨会话不失忆、按项目约束干活**。

具体:
- **G1 采用,不重造**:直接用 mattpocock 的 skill 骨架跑陪伴流。
- **G2 补记忆层(核心差异化)**:一个纯 markdown、手动维护的项目记忆层——记忆/状态/追溯 + roadmap + init。这是 mattpocock 没做全、也是我们真正的增量。
- **G3 只补真缺口**:实测确认咬人的,才补 skill。
- **G4 全程手动可跑**:不依赖任何机器门禁,假设 AI 不折扣执行 AGENTS.md + 指向的 md + skill 提示。

**成功长啥样**:拿一个真实项目,AI 能从 init 建好记忆层 → 陪伴式做任务 → 压缩/换会话后靠记忆层复位不跑偏 → 教训沉淀进记忆层下次生效。全程无脚本。

---

## 二、范围(明确 in / out)

**✅ In(做)**
- 陪伴型架构;Codex 为主 host(Claude Code 顺带能用即可)
- mattpocock skill 采用 + 项目记忆层 + init + 有限补缺
- 纯 markdown、手动维护

**❌ Out(明确不做,防跑偏)**
- 机器门禁 / git hook / 完成权脚本 / 状态机脚本 —— **v1 就死在这**
- 分解编排型架构 —— 留给 `flow-ultra-max`
- 无人值守 / 多任务并行 —— 陪伴是全程在场
- 发布 / 部署 / 回滚 —— 陪伴开发止于 commit
- 跨全部 host 的通用性保证 —— 先只保 Codex

## 三、步骤(gated,做完打勾)

### P0 · 实测 mattpocock 真身(**你来**;gate:无)
**目的**:验证陪伴流在 Codex 跑不跑得通 + skill 机制 + **收集真实缺口**。不建任何东西。
- [ ] 装 mattpocock 全套到 Codex(`npx skills@latest add mattpocock/skills` 或 clone → `.agents/skills/`)
- [ ] 验最基础的:skill 能被发现、`/名` 能手动触发
- [ ] 跑一个真实小任务:`/grilling → /to-prd → /to-issues → /implement`
- [ ] 逐项记结论到研发日志:
  - [ ] 跨会话教训会不会**蒸发**?
  - [ ] 重构会不会**漏掉已有功能**?
  - [ ] 会不会**没测就说完成**?
  - [ ] **新开一个会话**接着做同一任务(最常见的上下文清零,不需要大项目):新会话知道**做到哪、项目约束、上次教训**吗?(裸 mattpocock 大概率不知道——这是记忆层最日常、最好测的理由)
  - [ ] (可选,需大项目/长会话才会遇到)真跑到**触发压缩**了,压缩后接不接得上?顺手记一下,别专门为它造大项目
  - [ ] `code-review`(Codex 无 subagent fork)够不够狠?
  - [ ] 有没有"**项目约束/roadmap 没地方放**"的别扭?
- **完成判据**:研发日志里有一条「P0 实测结论」,列出确认的真缺口。

### P1 · 定向深读记忆层最佳实现(**我来**;gate:P0 确认要建记忆层)
- [ ] 深读 helloagents:`.helloagents/` 结构、`~init` 行为、`STATE.md` 模板、旧项目怎么扫描填充
- [ ] 深读 gsd:`ROADMAP.md` 形态、`map-codebase`(旧项目 init)
- [ ] 瞄 maestro:`decisions.ndjson`(追溯层做法)
- [ ] 产出 `设计-记忆层.md`:确切文件结构 + init 行为(手动版)
- **完成判据**:有一份记忆层设计文档,你认可。

### P2 · 手动搭记忆层(gate:P1)
按三层落成具体模板:
- [ ] **记忆层**:`AGENTS.md` 骨架(耐久约束 + "碰某块先读某 md"的按需加载规则)
- [ ] **记忆层**:大块约束(前端/后端/风格)的 reference md 组织方式
- [ ] **状态层**:`STATE.md` 模板(≤N 行、单文件重写、复位友好)
- [ ] **追溯层**:决策记录文件形态(追加式)
- [ ] **roadmap 层**:项目级 `ROADMAP.md` 模板(计划 + 进度分开)
- [ ] **init**:新项目建这些文件的说明 + 旧项目扫码反推填充的说明
- [ ] 一个"记忆层怎么维护"的 skill/说明(让 AI 按它读写)
- **完成判据**:拿一个真项目手动套一遍,AI 能读能维护、压缩后能复位。

### P3 · 补真实缺口(gate:P0 结果,不疼不补)
- [ ] 复盘沉淀件(教训回写 + 毕业进 AGENTS.md)—— 若 P0 确认蒸发
- [ ] 重构反查件(对照 spec 查 missing)—— 若 P0 确认漏
- [ ] 其余按 P0 实际疼的补
- **完成判据**:每个补的件都对应 P0 的一条真缺口,不无中生有。

## 四、防跑偏纪律(每步自检,从 v1 失败换来的)
1. **先定架构再动手**,不骑墙(companion-light 就是 companion-light,不掺分解型机器)。
2. **skills-first**:先让流程手动跑通,再谈任何机器件。
3. **痛点驱动**:缺口是**实测**出来的,不是想象的。
4. **早在真 host 验**:别又攒一堆没在 Codex 里跑过的东西。
5. **先理解再动手**:涉及 skill 机制/框架细节,查证再说。
6. **诚实标注**:抄来的标来源,自组的标自组,没验的标没验。
