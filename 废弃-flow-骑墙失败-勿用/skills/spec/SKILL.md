# 写清规格

把已经对齐的意图写成仓库根的 `spec.md`。格式严格如下——它同时会被 `verify.sh` 当门禁跑,格式不对门禁就读不到。

前置:确认 `.flow/approved` 存在(grill 已对齐)。没有就先去 grill。

`spec.md` 四段:

1. **Requirements** — 逐条编号 `R1`/`R2`…,一句话一条,编号不复用(可追溯)。
2. **Seams** — 你打算在哪些**公开边界**验收(CLI/API/UI 级)。实现前先在这里写死并与用户确认,不测内部实现。
3. **Acceptance** — 每条 AC 标它验证哪条需求 `(R#)`,并配一条 `verify:` 命令:
   - 命令绿 = 通过。
   - 必须走**真实端到端路径**;禁止 import 内部模块来"证明"通过。
   - 写不出可跑命令 = 没想清楚,退回澄清。
4. **Out of scope** — 明确不做的,防实现时手痒多写。

写完自检:每条 `R` 都至少有一条 `AC` 覆盖?每条 `AC` 都有 `verify:`?

交接:`spec.md` 交给 slice 切片;`verify.sh` 读它跑门禁。格式模板见同目录 `EXAMPLE.md`。
