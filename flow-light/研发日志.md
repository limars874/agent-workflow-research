## 2026-07-07 · 开新目录,重来

**背景**:前一个尝试 `废弃-flow-骑墙失败-勿用/`(v1-hybrid)已退役。失败根因三条:
1. **骑墙**——背着"分解编排型"的重外化状态(`.flow/` 契约、per-slice 完成权门禁),执行却是"陪伴型",两套架构各拿一半。
2. **建反顺序**——enforcement-first,让 skill 迁就脚本。正确应 skills-first、痛点驱动加机器件。
3. **skill 认知不足**——最初把 skill 当"手动让 AI 读文档",不懂它靠目录自动发现 + `/名` 手动触发 + description 自动触发。

**这次的定调(讨论收敛的)**:
- **命名**:`flow-light`(家族 `flow-*` 按架构分:light=陪伴轻量、ultra-max/max=分解编排重版)。用户早前就定了这个方案,我一度失忆现编了别的名字,已纠回。
- **架构**:companion-light(陪伴轻量),**不掺分解编排型的重机器**。
- **目标 host**:Codex(上下文可持续性强,压缩不跑偏)。
- **机器门禁/脚本**:**暂缓**。先纯手动、假设 AI 不折扣执行 AGENTS.md + 指向的 md + skill 提示。
- **核心要建的**:**项目记忆层**(不是机器门禁)。

**关键认知(这次的地基)**:
- **上下文可持续性决定架构**:高可持续(Codex)→ 轻陪伴;低/小窗口 → 才需要分解编排 + 重外化状态。别搞反。
- **项目记忆 = 三层**,读写模式不同,必须分开:
  - 记忆层(耐久:约束/规范/蓝图)→ 放 `AGENTS.md` + 指向的 reference md
  - 状态层(易变:任务内进度/复位上下文)→ 一个工作文件,开工/压缩后读
  - 追溯层(增长:决策记录)→ 追加式
- **框架的两个洞**(我们 8+8 之前没覆盖):**init**(项目初始化 + 旧项目扫描反推记忆)、**roadmap**(项目级多任务轨迹,在 per-task 之上)。
- **记忆层照 helloagents 抄**:它的 `.helloagents/{context.md,guidelines.md,DESIGN.md,modules/*.md}` + `~init` + `STATE.md(≤70 行单文件重写)` 几乎就是我们要的,且 Codex 原生。剥掉它的 hook/脚本/No-Refusal 条款即可。roadmap 抄 gsd `ROADMAP.md`,旧项目 init 抄 gsd `map-codebase`,追溯层抄 maestro `decisions.ndjson`。

**认知修正(同日)**:记忆层的真正价值是**对抗上下文丢失**,而丢失最常见、最好测的形态是**新开会话**(上下文直接清零,不需要规模),不是**压缩**(罕见、要大项目才触发,小任务填不满 200k+ 窗口)。所以验证记忆层需求,测"新会话还记不记得",别去造大项目测压缩。这也说明记忆层是**日常刚需**(每次新会话都需要),不只是大项目才需要——反而更强化了它的必要性。

**方法修正(同日,第二次)**:砍掉原计划的"P0 玩具试跑发现缺口"。两个理由(用户指出):①玩具任务小到不用框架自己就做,测不出框架价值——这些框架**本来就是给非小规模项目用的**;②"裸 mattpocock 新会话会不会失忆"是**必然结论**(记忆层没建当然失忆),验它没意义。**缺口不需要发现——已知就是记忆层**(用户 trellis 实战 + 我们的分析)。所以改成:先设计对(P1 深读)→ 搭轻量版(P2)→ **在用户真实项目上 dogfood 验证**(P4,唯一有意义的验证:"有了记忆层灵不灵",不是"没有会不会忘")。

**下一步**:P1——深读 helloagents/gsd 的记忆层与 init,产出设计。可立即开始(不再 gate 在玩具试跑上)。

## 2026-07-09 · P2 落地 + skill 化重做(一大串,补记)

**P2 初版**:按 5 项决策落成记忆层模板(AGENTS 块 + PROGRESS/constraints/ROADMAP/learnings 模板 + `/flow-init`),纯 markdown 零脚本。

**用户点出问题 → 三轮返工(都是真改进)**:

1. **"空模板不够,每模块该有 skill;去读 mattpocock 的 writing-great-skills"**。读了他的 meta-skill,学到:调用方式(model vs user invoked 各付一种成本)、信息阶梯 + 完成判据、leading word、失败模式(negation/no-op/duplication/sediment)。据此把 craft 从"散在空模板注释"提升成正经 skill。
   - 判据:**只有"agent 必须靠 leading word 自动够到"才值 model-invoked**;否则 user-invoked 或只留模板。
   - 结果:flow-reflect(model,leading word=lesson)、flow-progress(先误标 user,**纠正为 model**——agent 要自动触发,user-invoked 模型够不到)、flow-init(user,一次性)。roadmap/constraints 不单独成 skill。

2. **"flow-init 和 setup 风格/措辞比过吗"**。没比过,一比差挺多。→ 决策:**结构向 setup 对齐**(Explore→Present→Write→Infer→Confirm,explore-first + 走用户 + 写前给草稿)、**全套英文**与 mattpocock 同族(段名英文,内容随用户中文)。

3. **"样板该拆开、和 SKILL 同目录(看 domain-modeling)"**。读真身,学到他惯例:**SKILL 只放 craft,FORMAT/样板拆成同目录 sibling,`./指针`引**,无独立 templates 目录。据此重构:PROGRESS-FORMAT/CONSTRAINTS-FORMAT/ROADMAP-FORMAT 各归位,消除 flow-progress 与模板的 duplication(单一真源)。

**flow-init co-location 修复**(用户点):memory 节要**跟着 setup 落到同一个文件、挨着它放**(探测 `## Agent skills` 在哪),不劈叉 AGENTS/CLAUDE;无 setup 时沿用 setup 自己的选文件规则。

**新增 journal 层**(用户点"PROGRESS 是快照,没纯开发日志"):去读 trellis 真身(session-insight + workspace-memory)。抄到三样——**三 store routing**(任务态/journal/spec 各一线)、**"能力非仪式"**哲学(治 journal 变噪音)、**两种 journal 形态**(写出来的 + 检索原始 JSONL;后者=Codex 日志本已存在,检索工具 defer 机器层)。落成 flow-journal skill + JOURNAL-FORMAT。**决策:journal 与 learnings 各一条线,不合并**(trellis 的 learnings→spec 回写和 journal 也是分开的)。

**记忆层现状**:4 个 skill(flow-init / flow-progress / flow-reflect / flow-journal),每个 SKILL(craft)+ FORMAT sibling,全英文、与 mattpocock 同惯例。三条 trace 分工:journal(时间线)/ PROGRESS(快照)/ learnings(蒸馏)。

**方法反思**:这一段没再骑墙、没再 enforcement-first,基本是"用户点问题 → 去读源头真身 → 校准 → 改",比 v1 那种埋头搞健康得多。教训:**涉及 skill 惯例先读 mattpocock 真身,别凭原则外推**(writing-great-skills / setup / domain-modeling 三次都是读了真身才做对)。

## 2026-07-09 · 命名与 draft 语义修正

**背景**:在 `dialog-jumper` dogfood 前评审 flow-light 记忆层,发现两个设计味道问题:一是 `PROGRESS.md` / `ROADMAP.md` 与其他小写文件混用;二是 brownfield init 从代码反推出的 constraints/roadmap 容易被误当成已确认事实。

**决策**:
1. 生成到项目 `docs/` 的 memory 文件统一小写:`progress.md`、`roadmap.md`、`constraints.md`、`learnings.md`、`journal.md`。
2. `constraints.md` 与 `roadmap.md` 使用**文件级 Status**,不按条目混 `confirmed/inferred/needs-confirmation`。
3. `constraints.md` / `roadmap.md` 的 status 按内容来源定:owner-provided / owner-confirmed 可 `Status: confirmed`;模型从代码、历史或常识推断/补全的内容为 `Status: draft`。
4. `Status: draft` 或缺失 status 时,agent 只能把文件当 review context / planning input,不能当 binding rule 或 committed direction。

**原因**:constraints/roadmap 语义上应是正式规则/方向。文件内长期混状态会污染正式文档;但 init 又需要能先生成草稿。因此文件级 status 是更清晰的折中。

## 2026-07-09 · 约束反推过度锁定 → 回归 gsd/trellis 修正

**背景**:用户在真实小项目 dogfood flow-init,发现反推的 constraints **过度把当前结构/MVP机制提升成永久约束**(如"NativeDialogDetector 独占AX"、把 keybinding 写进架构约束)。

**根因(回归确认)**:①我们约束反推抄了 **gsd 的 map-codebase,但那是"代码地图"(描述现状供理解)不是"约束"**——扫码天然吐结构清单。②`trellis` 的 `spec/`(=工程约定/约束)才是正主,我们没参考。

**trellis 教的(比 gsd 对)**:spec=" 如何在**这个仓库**工作";**Write From Evidence**(文件是证据不是规则主语);AVOID **"rule based on a single accidental implementation detail"**(正中 MVP 机制病);Example Shape=模式/边界 + Reference files + Avoid;两条建 spec 路(bootstrap + 增量 update-spec)恰好=我们 flow-init + flow-reflect,**架构本对,只是 flow-init 该学 trellis 的 spec-writing 而非 gsd 的 map**。

**修正**:CONSTRAINTS-FORMAT + flow-init step4 用 trellis 表述升级——constraint=durable 局部模式(非结构非通用),write-from-evidence,Example Shape 带 Evidence/Avoid,few boundaries。存档 `研究/trellis-spec-约束.md`。

**方法教训(又一次)**:参考源要参考**对定位的那个**——约束该看 trellis spec,不是 gsd map。dogfood 的真反馈 + 回归正确源头,比闭门改十遍强。待用户重跑 flow-init 验证是否还过度。

## 2026-07-12 · 记忆层 skill 评审修正(5 处)

**背景**:dogfood 前对 9 个 skill/FORMAT 文件做了一轮逐文件评审,发现两个逻辑漏洞、两处跨 skill 接缝、一处含糊表述,全部修掉:

1. **P1 host 可读性**(flow-init step 2):原选文件规则沿用 setup("CLAUDE.md 优先"),但 Codex 只读 AGENTS.md——只有 CLAUDE.md 的仓库会把 memory block 写进 host 读不到的文件。加"Host-readability check(压过 co-location)":落点文件 host 不自动加载时,停下和用户定(通常建 AGENTS.md)。
2. **P2 毕业 vs 文件级 Status**(flow-reflect step 3):confirmed 规则写进 draft 文件不 binding。改为:毕业时若 constraints.md 是 draft,即请 owner 通审全文件翻 confirmed;不翻则 lesson 留 learnings,不写进承载不了它的文件。
3. **P3 触发仲裁**(AGENTS-memory-block):"each fires itself" 太含糊,同一事件可命中三个 skill。改为收尾序列:progress(状态变了就写)→ journal(有 replay value 才写)→ reflect(教训值回时间才写),同一内容绝不写两处。
4. **P4 跨 skill 引用**(flow-init step 3/5):"see the flow-progress skill's PROGRESS-FORMAT.md" 无真路径,模型未必找得到。progress 初始骨架直接内联(仅 5 段标题),journal 首条内联字段名;格式所有权仍归各 skill。
5. **P5 零散**:learnings/journal 日期注明取自环境或 `date +%F`,不许猜;AGENTS block 里 "for decisions read docs/adr/, CONTEXT.md" 拆为"决策理由归 adr、术语归 CONTEXT"(与 CONSTRAINTS-FORMAT 的分工对齐)。

**未改、留 dogfood 观察**:flow-progress 触发频率偏高("meaningful step" 每几轮命中一次,整文件重写)是否成噪音税;model-invoked 触发在真 Codex 里仍未实测。
