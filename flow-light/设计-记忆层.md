## 2. AGENTS.md 内容(Codex 免 hook 读回的核心)

AGENTS.md 里放两块(都是纯文本规则,Codex 每会话自读):

**A. 读取优先级规则(抄 helloagents 三层 + 主线判断)**
```
## 记忆层读取规则
- 开工/新会话/延续任务:先读 docs/progress.md 复位(确认当前消息仍是同一任务再采信它)
- 理解项目:读 docs/constraints.md + CONTEXT.md;constraints 若为 `Status: draft` 或缺失 status,只当 review context,不当规则;碰前端读 frontend.md,碰后端读 backend.md
- 深入:docs/adr/、docs/learnings.md
- 主线判断优先级:当前用户消息 > 代码与验证证据 > confirmed memory > progress(只补进度) > draft memory/history
- 收尾/commit 前:重写 progress.md(自检:现在若压缩/换会话,下一轮能凭它找回进度吗?不能就是没写好)
```

**B. 指针块(抄 mattpocock `## Agent skills`)**
```
## Agent skills
### Project constraints — See docs/constraints.md (binding only when `Status: confirmed`)
### Session progress — See docs/progress.md
### Roadmap — See docs/roadmap.md (directional only when `Status: confirmed`)
(+ mattpocock setup 原有的 issue-tracker / triage-labels / domain 三条)
```

## 3. progress.md 模板(复位状态,抄 helloagents STATE.md)

**≤70 行,5 段,单文件重写(非追加),只记当前状态不记历史:**
```markdown
# 恢复快照
## 主线目标
[一句话:当前连续任务真正要完成什么]
## 正在做什么
[当前任务 + 正在执行的具体步骤,无则"空闲"]
## 关键上下文
[复位必需的最小信息:关键决策、已改文件+变更摘要、当前假设。不相关的删掉]
## 下一步
[具体到能立即执行,含文件路径]
## 阻塞项
[无 / 具体阻塞]
```
写入点:implement 收尾、code-review 后、每次 commit 后。读取点:每个新会话开工。**手动版=LLM 直接 Read/Write 这个文件,无脚本。**

---

## 4. roadmap.md(项目级,抄 gsd)

- 三层:**里程碑 → 阶段 Phase → Plan**(轻量版可只用 Phase + checklist)
- 每 Phase:Goal / 依赖 / Success Criteria(用户视角可观察)/ Plans 清单(`- [ ]/[x]`)
- 底部 Progress 表:`Plans Complete (n/m) + Status`
- 无时间估算。读:grill/to-prd 开工对齐方向;写:里程碑推进时。

## 5. init 设计(新项目 + 旧项目)

一个 flow-light-native 的 `/init`(纯 prompt,抄 helloagents 两阶段 + gsd map-codebase 扫描思路):
- **阶段1(无条件)**:建 `docs/` + 空 progress.md;把 §2 的规则+指针块写进 `AGENTS.md`(有 `## Agent skills` 块就扩,没有就建)。constraints.md 与 roadmap.md 初次生成都带 `Status: draft`,用户确认后才改 `confirmed`。
- **阶段2(旧项目=有代码)**:LLM 读代码库反推填充——
  - `constraints.md`:从代码/配置推断技术栈约束、架构约束、风格约束(抄 gsd map-codebase:按 tech/arch/style/concerns 几个焦点扫,**每条约束带反引号文件路径为证**),但仍是 draft
  - `CONTEXT.md`:领域术语;`roadmap.md`:仅用户明确需要时从现有功能反推里程碑草稿,不能自动当 owner-approved 方向
  - 幂等:已有文件增量更新不覆盖手改(抄 helloagents)
