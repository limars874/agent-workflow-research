# AI Agent 编码 Workflow 能力框架研究

对 11 个开源 AI agent 编码 workflow / skill 框架的逐仓库深读,回答一个问题:

> **一个好的 agent 编码 workflow 应该具备哪些能力和步骤?**

不是逐个仓库的 README 复述,而是从**失败模式**反推出一套统一的能力框架,再用同一把尺子给 11 个框架打分、对比、给出组合建议。

---

## 核心结论(TL;DR)

- **框架 = 8 步主流程 × 8 项横切能力 × L0–L3 成熟度**。步骤是时序,横切能力贯穿全程,成熟度衡量"机器强制还是 prompt 自律"。
- **一条分水岭贯穿始终:机器强制 vs prompt 自律。** prompt 自律的致命缺陷是**失效静默**——模型违规那一次你收不到告警;hook 拦截失败会直接报错。前者靠运气发现,后者靠机制发现。
- **"全能框架"不存在。** 16 维中 L3 过半的只有 consensus-rnd 一家,代价是极高接入成本 + 无前段人机交互 + 每任务小时级通信税;其余十家 L3 都不超过 5 格。存在的是四种原型:**前段规格型 / 执行闭环型 / 后段门禁型 / 记忆沉淀型**——选型 = 按失败模式选原型,再跨原型按机制拼装。
- **两个可带走的判断标准**:评估任何 workflow,先问①哪些环节是机器强制的?②完成权在谁手里(LLM 能不能自己写下 "done")?
- **四个生态空白**:可控发布的"接缝"(生产回滚信息回不到 dev)、复盘沉淀双环(仅 2 家闭合)、存量重构专用流程(0 家)、多任务协调的轻量选项(只有重型的 consensus-rnd)。

## 能力框架一览

```
主流程(8 步):
  S1 澄清意图 → S2 写清规格 → S3 小步切片 → S4 实现功能
  → S5 验证证据 → S6 独立审查 → S7 可控发布 → S8 复盘沉淀
                                   ↑生态空白      ↑仅 2 家闭环

横切能力(8 项,贯穿全程):
  C1 任务状态   C2 上下文治理   C3 记录与追溯   C4 安全护栏
  C5 完成权剥夺   C6 跨host可移植   C7 机器下沉   C8 无人值守与多任务并行

成熟度:L0 缺失 → L1 Prompt 自律 → L2 状态落盘 → L3 机器强制
```

其中 **C5 完成权剥夺**(LLM 不能自证完成)与 **C8 无人值守与多任务并行**是本研究相对既有讨论新增/独立出来的维度。

## 研究方法

逐仓库深读(2026 年年中的仓库状态),每个仓库产出一篇独立报告,再两步归纳:先从失败模式反推能力框架,再用统一口径(判级看**最弱链**,每格评分可回溯到具体机制)对 11 框架做 16 维评分。

**局限**:评分基于仓库文档与代码静读,未做同任务实测跑分(仅 Trellis 与 consensus-rnd 有作者本人的 n=1 使用体验作为注脚);框架迭代快,L 级判定以深读时点的版本为准。
